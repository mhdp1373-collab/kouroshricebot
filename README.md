# ربات مدیریت مستندات بارنامه (پی‌بار) — نسخه بله + داشبورد وب ادمین

## فایل‌ها
- `bot.py` — کد اصلی ربات + بک‌اند داشبورد وب (FastAPI)، همه در یک پروسه
- `dashboard.html` — صفحه‌ی داشبورد وب ادمین (باید کنار `bot.py` باشد)
- `requirements.txt` — پکیج‌های پایتون مورد نیاز
- `Procfile` — دستور اجرا برای Railway/Heroku
- `.env.example` — نمونه‌ی متغیرهای محیطی مورد نیاز
- `.gitignore` — جلوگیری از آپلود فایل‌های حساس/موقت

## راه‌اندازی روی Railway

1. این ریپو رو به گیت‌هاب پوش کن (دقیقاً همین فایل‌ها، از جمله `dashboard.html`، به‌جز `.env`).
2. در Railway یک پروژه‌ی جدید از روی این ریپو بساز.
3. در تب **Variables** سرویس، متغیرهای زیر رو تعریف کن:
   - `BOT_TOKEN`
   - `ADMIN_IDS`
   - `STORAGE_CHANNEL_ID` (اختیاری)
   - `ADMIN_USERNAME` (اختیاری، پیش‌فرض `@koroshrice`)
   - `DASHBOARD_TOKEN` — یک رمز طولانی و تصادفی بساز (مثلاً با `openssl rand -hex 24`)؛ این رمز کلید ورود به داشبورده، حتماً محرمانه نگهش دار.
4. روی Railway باید **Networking** رو برای این سرویس فعال کنی تا یک آدرس عمومی (Public Domain) بگیره — از تب **Settings → Networking → Generate Domain** استفاده کن. Railway به‌صورت خودکار متغیر `PORT` رو تزریق می‌کنه؛ نیازی نیست دستی تنظیمش کنی.
5. اگه Railway دستور اجرا رو پیدا نکرد، در **Settings → Deploy → Custom Start Command** بنویس: `python bot.py`
6. اگه سرویس بعد از دیپلوی مدام ری‌استارت می‌شه، **Healthcheck** رو غیرفعال کن یا مسیرش رو روی `/` بذار (چون از این پس سرویس یک وب‌سرور هم داره، این خط ممکنه لازم نباشه).

## استفاده از داشبورد

بعد از دیپلوی موفق، آدرس عمومی که Railway بهت داد (مثل `https://xxxx.up.railway.app`) رو در مرورگر باز کن. صفحه‌ی ورود، همون `DASHBOARD_TOKEN` که در Variables گذاشتی رو ازت می‌پرسه.

در داشبورد می‌تونی:
- همه‌ی بارنامه‌ها رو بر اساس وضعیت (در انتظار / تایید شده / رد شده / کسری بار) فیلتر و جستجو کنی
- مستندات هر بارنامه رو ببینی
- مستقیماً تایید / عدم تایید (با ذکر علت) / تایید با کسری بار (با ذکر مقدار) بزنی — دقیقاً همون پیام‌هایی که از طریق خود ربات به راننده ارسال می‌شد، از داشبورد هم ارسال می‌شه
- یک پیام آزاد و دلخواه برای راننده‌ی هر بارنامه بنویسی و بفرستی

هر اقدامی که از داشبورد بزنی، دقیقاً هم‌زمان روی خودِ ربات بله هم منعکس می‌شه (پیام به ادمین‌های دیگه، حذف دکمه‌های قدیمی و غیره) — چون داشبورد و ربات از یک دیتابیس و یک پروسه استفاده می‌کنن.

## اجرای محلی (تست روی سیستم خودت)

```bash
pip install -r requirements.txt
cp .env.example .env   # بعد مقادیر واقعی رو داخلش بنویس
python bot.py
```

بعد از اجرا، داشبورد روی `http://localhost:8080` در دسترسه.

## نکات مهم
- توکن ربات رو حتماً از `@Bot_Father` **داخل خودِ بله** بگیر، نه تلگرام.
- فایل `.env` هرگز نباید به گیت‌هاب آپلود بشه.
- فایل `database.json` بعد از اولین اجرا خودکار ساخته می‌شه؛ روی Railway این فایل با هر ری‌دیپلوی از بین می‌ره (فضای ذخیره‌سازی موقتیه) مگر یک Volume دائمی وصل کنی — برای نگه‌داری دائمی داده‌ها این کار رو جدی بگیر.
- `DASHBOARD_TOKEN` رو فقط به ادمین‌های مورد اعتماد بده؛ هرکس این توکن رو داشته باشه می‌تونه بارنامه‌ها رو تایید/رد کنه.
